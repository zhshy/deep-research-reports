## 方法论

每篇报告遵循同一个七层结构（详见 [deep-dive-investment-report](https://github.com/zhshy/deep-dive-investment-report)）：

```
Phase 0  立题      口语问题 → 可证伪命题
Phase 1  估值坐标  双口径分位 / 极值空间 / PE-PB-ROE 三角 / ERP / 比价 / 板块冷热
Phase 2  归因分解  ln P = ln E + ln PE，跌因拆成贡献占比
Phase 3  传导链    需求源头 → 现金流转向 → 定价范式切换 → 标的层体检
Phase 4  判别      八项判据双层加权 → 风险归属 → 剔除测试 → 案例校准 → 分歧点表态
Phase 5  情景定价  三情景映射 / 赔率双口径 / 隐含预期反推 / 敏感性矩阵 / 脆弱假设
Phase 6  节奏      三层底（估值/价格/时间）+ 历史回撤统计 + 两融与被动资金
Phase 7  框架重建  风险预算定仓位 / 逻辑条件 C1–Cn / 三折扣触发矩阵 / 逻辑失效止损
```

**七条铁律**：口径先行 · 参照系决定含义 · 归因优于描述 · 双层结论允许相反 · 每个判断配证伪锚点 · 主观概率不配仓位话语权 · 框架必须匹配使用者纪律。

## 目录结构

```
.
├── README.md                    本文件（自动生成的索引）
├── TEMPLATE.md                  每日报告模板（复制即用）
├── reports/
│   └── YYYY-MM-DD/
│       ├── A股与创业板深度研究-YYYY-MM-DD.md   当日正文
│       └── scenarios.json                       当日三情景参数（可复算）
└── scripts/
    ├── calc.py                  计算器：分解/判据/情景/敏感性/仓位/风险/ERP
    ├── build_index.py           扫描 reports/ 重建本 README 的索引表
    ├── ghpush.py                Git Data API 原子提交（无需 git clone/push）
    └── publish.sh               一键发布：建索引 + 推送
```

## 每日怎么发一篇

1. **写**：把当日正文放进 `reports/YYYY-MM-DD/`，文件名 `A股与创业板深度研究-YYYY-MM-DD.md`，骨架直接抄 `TEMPLATE.md`。
2. **算**：所有派生数字用 `scripts/calc.py` 复算，不要手算。命令写进正文附录 B，读者可自行验证。
3. **发**：

```bash
GH_TOKEN=<你的 PAT> bash scripts/publish.sh "release: 2026-11-05 日报"
```

脚本会先重建 README 索引，再按 blob SHA 差分只上传变动的文件，最后逐字节回验。

4. **只想更新索引、不推送**：

```bash
python3 scripts/build_index.py
```

## 写作约定

- **核心结论前置**：第一屏必须能拿到判断，读者不需要滚动。
- **数字全部可复算**：表格合计要等于列内之和；情景矩阵每一格都要能由 `P×(1+g)×(PE/PE₀)` 复算，只校验对角线会漏掉边缘格。
- **未通过的检查项要写出来**：附录 C 列出自检 67 项里哪几项没过、为什么没过。这比全部打勾更有信息量。
- **口径缺口单列一节**：拿不到的数据（如板块十年估值分位、前瞻 PE 覆盖率）必须写明"未取得"，不能用估计数替代。
