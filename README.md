## 方法论

每篇报告遵循同一个七层结构（详见 [deep-dive-investment-report](https://github.com/zhshy/deep-dive-investment-report)）：

```
Phase 0  立题      口语问题 → 可证伪命题
Phase 1  估值坐标  双口径分位 / 极值空间 / PE-PB-ROE 三角 / ERP / 比价 / 板块冷热
Phase 2  归因分解  ln P = ln E + ln PE，跌因拆成贡献占比
Phase 3  传导链    需求源头 → 现金流转向 → 定价范式切换 → 标的层体检
Phase 4  判别      八项判据双层加权 → 风险归属 → 剔除测试 → 案例校准 → 分歧点表态
Phase 5  情景定价  三情景映射 / 赔率双口径 / 隐含预期反推 / 敏感性矩阵 / 脆弱假设
Phase 6  节奏      三层底（估值/价格/时间）+ 历史回撤统计 + 两融与被动资金
Phase 7  框架重建  风险预算定仓位 / 逻辑条件 C1–Cn / 三折扣触发矩阵 / 逻辑失效止损
         └─ 9.5 战术执行交接（条件项）：战略授权 → 战术触发 → 可复核归档
```

**七条铁律**：口径先行 · 参照系决定含义 · 归因优于描述 · 双层结论允许相反 · 每个判断配证伪锚点 · 主观概率不配仓位话语权 · 框架必须匹配使用者纪律。

## 战术执行快照（`signals-*.json`）

报告写到"该等什么"就停，读者仍然不知道**今天这个价位规则允不允许动手**。这个缺口由 [divergence-trade-signals](https://github.com/zhshy/divergence-trade-signals) 引擎补上：输入日线 OHLCV，输出可复核的技术状态，**不产生新的战略结论**。

```
研报（战略层）        明确"值得买、买多少"        →  strategic_authorization
        ↓
引擎（战术层）        明确"现在能不能下手"        →  execution_blockers / selected_setup
        ↓
归档（signals-*.json） 版本号 + 输入 SHA256       →  第三方可逐字节复算
```

**四层不许互相代答**：战略层不回答买点，技术层不回答仓位，执行层不回答方向，市场规则层（T+1 / 涨跌停 / 不可裸空）不回答价值。

| 技术状态 | 含义 | 允许的输出 |
|---|---|---|
| `TRIGGERED_LONG` / `TRIGGERED_SHORT` | 最新已收盘 K 线上刚触发 | 唯一可能成为买点的状态 |
| `WAIT_TRIGGER_LONG` / `WAIT_TRIGGER_SHORT` | 结构成立但未触发 | 只报条件，不报价格 |
| `EXPIRED_DO_NOT_CHASE` | 触发早已发生，价格已跑过 | 明确写"不可追" |
| `NO_SETUP` | 规则沉默 | **不表示看多或看空** |

**三条硬约束**：A 股 T+1、不可裸空（空头背离只输出"不加仓/减仓/退出"）；核心仓不用技术止损；`NO_SETUP` 一律不得写成方向判断。

复现命令见各期报告附录 B。名单与"该等什么"只维护一份 `leaders.json`，技术判定全部由引擎计算，避免双份维护。

## 自动发布

每周一至周五 **12:40（午间）** 与 **15:40（收盘）** 各自动出一份，抓数据 → 写研报 → 生成摘要网页 → 推送。非交易日自动跳过（会先查交易日历）。

| 时段 | 数据基准 | 文件命名 |
|---|---|---|
| 午间 12:40 | 上午 11:30 收盘（标注"午间快照"） | `...-YYYY-MM-DD-午间.md` / `...-YYYY-MM-DD-午间.html` |
| 收盘 15:40 | 当日 15:00 收盘 | `...-YYYY-MM-DD-收盘.md` / `...-YYYY-MM-DD-收盘.html` |

索引会自动识别 `午间` / `收盘` 两个时段，收盘版排在前面。**发布令牌存在 macOS 钥匙串**（服务名 `workbuddy-gh-token`，账号 `deep-research-reports`），`publish.sh` 会自动读取，不需要在命令里写令牌。

## 每日怎么手动发一篇

1. **写**：把当日正文放进 `reports/YYYY-MM-DD/`，文件名 `A股与创业板深度研究-YYYY-MM-DD.md`，骨架直接抄 `TEMPLATE.md`。
2. **算**：所有派生数字用 `scripts/calc.py` 复算，不要手算。命令写进正文附录 B，读者可自行验证。
3. **发**：

```bash
GH_TOKEN=<你的 PAT> bash scripts/publish.sh "release: 2026-11-05 日报"
```

脚本会先重建 README 索引，再按 blob SHA 差分只上传变动的文件，最后逐字节回验。

4. **只想更新索引、不推送**：

```bash
python3 scripts/build_index.py
```

## 写作约定

- **一天两份也可以**：全文回答"为什么"，摘要回答"买什么/不买什么/什么时候动手"。摘要在索引里排在全文之前，因为它是入口。摘要页固定五块——核心结论 / 板块冷热 / 热点冷门 / 龙头点评 / 短期与长期，**顺序不可颠倒**。
- **网页版固定叫 `summary.html`**：文件名用 ASCII，URL 才干净（中文文件名在 Pages 上会被百分号编码）。页面顶部要有「返回索引 / Markdown 版 / 当日全文」三个导航。
- **核心结论前置**：第一屏必须能拿到判断，读者不需要滚动。
- **数字全部可复算**：表格合计要等于列内之和；情景矩阵每一格都要能由 `P×(1+g)×(PE/PE₀)` 复算，只校验对角线会漏掉边缘格。
- **未通过的检查项要写出来**：附录 C 列出自检 75 项里哪几项没过、为什么没过。这比全部打勾更有信息量。
- **口径缺口单列一节**：拿不到的数据（如板块十年估值分位、前瞻 PE 覆盖率）必须写明"未取得"，不能用估计数替代。
- **技术状态一律机器算**：`NO_SETUP` 不写成方向判断，`EXPIRED` 不写成买点，午间版一律标 `forming` 且不得触发。
- **回测零交易也要报**：样本量、交易笔数、成本假设必须写出来。零笔交易是结论，不是失败，不能省。
